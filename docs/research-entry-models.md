# 研究用エントリーモデル（本番への組み込みなし）

## 今回の仮説と固定条件

総合スコアの閾値が全銘柄0.0である現行モデルを、そのまま`legacy_filters`として比較用に固定する。
新モデル`trend_follow_v1`は総合スコアを使わず、売買方向が一致する少数の指標条件を使う。
閾値・重み・銘柄別除外を探索してから仕様を選ぶ手順にはしない。

2026-11-23、成績を見る前に以下の1仮説を定義する。
「EMA・DI・MACDの向きが一致するトレンド継続の入口は、現行フィルター方式より説明可能で、費用込み損益の安定性を改善する可能性がある」。
これは利益を保証する仕様ではない。逆張りモデルや押し目からの再開モデルは今回追加しない。

| 条件 | ロング | ショート |
|---|---|---|
| EMAと価格 | close > EMA短期 > EMA長期 | close < EMA短期 < EMA長期 |
| DI | +DI > -DI | -DI > +DI |
| MACDヒストグラム | > 0 | < 0 |
| ADX | 25以上100以下 | 25以上100以下 |

直前2本の確定した15分足で、同方向の条件をそれぞれ満たす必要がある。
等値に方向性を認めない。ゼロ・負の価格、非数・無限大・真偽値・文字列・欠損や不正なDI/ADXは新規エントリーを禁止する。
足間隔の欠落・順序逆転・未来の足・古い足でも禁止する。

`buy_signal=short`、`sell_signal=long`という既存の共通判定関数への対応を維持する。
モデルは各確定足から独立にシグナルを計算し、2本連続の確認を維持する。
旧フィルターでFalseだったシグナルも、新モデルが満たせばTrueになり得る。旧条件に追加するフィルターではなく、独立した入口モデルである。

## 分離の境界

- 実装は`research/entry_models.py`。本番CLI・設定・注文・シャドーには接続しない。
- 既存の戦略コードと研究エンジン・キャッシュ生成コードも変更しない。
- モデル未指定および`legacy_filters`は元の`cache.prepare`を直接返し、計算やデータを書き換えない。
- `trend_follow_v1`は新規エントリーを検討する始値観測だけで、コピーした直前2本のフラグを差し替える。
- 未確定足の指標を参照しない。未確定足のフラグもFalseに保つ。
- 保有中の観測では元のシグナル履歴をそのまま返す。反対シグナルによる決済調整・利益保護・72時間制限を変更しない。
- キャッシュは共有データとして読み取り、候補シグナルを書き戻さない。
- 指定モデル名が不正なら開始前にエラーにし、現行モデルに黙ってフォールバックしない。

## 比較手順

研究用の実ソースバックテストへ`prepare_model(cache, model)`を渡す。手数料・保有費用・数量調整・資金管理・決済は既存処理を使う。
第一段階はモデルの正しさと現行の不変性を確認する検証であり、利益のあるモデルを選ぶ大量探索ではない。

検証する事項：

1. ロングとショートの対称性、ADX境界・等値・不正入力・各確定足・日時と足間隔。
2. 未確定足の改変や将来データの改変が、過去の判定に影響しないこと。
3. キャッシュ・元データ・保有中のシグナル・決済処理を変えないこと。
4. 実ソースのバックテストで取引が実際に発生し、方向・数量・費用・決済・再エントリー制限が整合すること。
5. 現行モデルの省略指定・明示指定が元のバックテスト結果と一致すること。
6. ネットワーク・DB・環境ファイル・通知を禁止した状態で完走すること。

公開データでの検証では過去の研究フォルダを上書きしない。入力・ソース・モデル仕様・コスト・期間の識別情報を保存する。
既に探索した2026年5〜11月は未使用の検証期間として扱わない。
Bitbank OHLCの代替価格・過去SR未再現・仮定費用・約定順序未再現という制約も継続する。
本番採用は今回の実装範囲に含めない。

## 実行と記録

`python -m pytest tests/test_entry_models.py -q`でモデルと実ソース再生のテストを実行する。
`python -m research.verify_entry_models`は、保存済みの2026-05-01〜05-03の公開足を7銘柄で再生する機能検証。
過去の特徴量キャッシュは読み取り専用とし、入力価格・キャッシュ・戦略ソース・研究コードのハッシュを照合する。
旧モデルは既存の高速研究再生とも約定・口座残高を比較する。
両モデルの全エントリー（期間末に保有中のものを含む）を照合し、決済分の価格・費用・純損益を別の計算式で検算する。

最終結果は`outputs/backtests/entry_models_20261123/verified/`へ保存する。
既存の検証計画とソース識別情報が変わった場合はエラーにし、異なる条件の結果を混在させない。
この短期間の損益は動作確認に限って使い、モデル採用の判断には使わない。
